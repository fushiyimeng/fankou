## 二、规则开关（`rules.json`）

| 开关 | 默认 | 含义与依据 |
|---|---|---|
| `JokerPairChainIsTractor` | `true` | 小王对 + 大王对算不算 2 连对。文档第 65 行说"两对王可以租拖拉机"，第 89 行用户又标注存疑。 |
| `TractorUsesNaturalOrder` | `true` | 拖拉机内部级牌不提权。依据文档第 28 行"连对里面包含的即使主，也没有别的大……4455 没有 6677 大"。 |
| `PairFillerPolicy` | `TrumpOnlyWhenVoid` | **空门**（一张该花色都没有）时必须垫主牌；有该花色但凑不齐结构时自由补。依据文档第 **102** 行。第 69 行那条旧规矩（有但凑不齐也要垫）留在 `TrumpOnlyWhenPartial` 档里可选。 |
| `TractorFollowPolicy` | `StructurePreserving` | 有连对必须出连对形状。依据文档第 90 行"有连队出连队"。 |
| `TopTripleIsThrow` | `true` | 顶牌（这门最大的两张 + 次大的一张）算不算甩牌。已实现，见第九节。 |

### 已经确认过的（不必再问）

- **副级牌算主牌，不算原来的花色。** 主黑桃打 5 时，♣5 就是主牌，出梅花时**不用**给出去。
  推论：`♣4455` 不是合法的连对——♣5 压根不算梅花，这一手是"主牌夹在副花色里"，两头不靠。
  文档第 28 行"连对里面包含的即使主"说的是**主花色的**连对（`♠4455`，那一组本来就全是主牌）。
  文档第 69 行那个括号"（这种梅花非主牌）"也是同一个意思：能当梅花使的只有非主牌。
  这条 2026-10-06 由用户当面确认，实现已按此改正（`Trump/FollowGroup.cs`）。

- **跟对子/拖拉机时，"必须垫主牌"的触发条件是空门，不是"凑不齐"。** 文档第 102 行原话：
  "有人打对子/拖拉机，自己手上有一张同花色非主的情况下，可以不用给主牌，但一张都没有的情况下，
  就必须垫主牌"。这条**推翻了第 69 行**（"手上只有一张梅花，那么你必须出一张梅花，然后再给一张主"）——
  两者触发条件正好互换，文档已经是新的，是代码没跟上。
  顺带：这条只管对子/拖拉机。领出**单张**时空门依然随便出（第 31 行），
  **甩牌**缺口也不要求垫主（第 72 行）。开关 `PairFillerPolicy`，旧规矩留在 `TrumpOnlyWhenPartial` 档。
  2026-10-06 用户确认。

  改这一条时踩的坑：`PairFillerPolicy` 这个开关**从做出来到 2026-10-06 一直是死的**——
  `RuleOptions` 里声明了、`rules.json`/`README`/游戏内帮助文本都写着它，
  但 `TrumpFillerRule` 和 `MoveGenerator` 都把旧行为硬编码了，没有任何代码读它。
  点菜单里那些说明是不会有反应的。现在校验器（`TrumpFillerRule`）和生成器（`MoveGenerator.FillerChoices`）
  共用 `TrumpFillerRule.MustFillWithTrump` 一个判据，别再让两边分家。

- **拖拉机必须同一花色，副主不能凑进去。** 文档第 98 行（2026-10-06 用户补充）：
  "你拿黑桃44和梅花55就不可以，必须是黑桃4455才算拖拉机"。
  连带推出：`♣55♣66` 也不是连对——♣5 在主牌组、♣6 在梅花组，不属同一门。

- **副主单打对子是合法的，而且很大。** 同一条：`梅花55` 要 `黑桃55`（本主对）或
  `小王小王` / `大王大王` 才压得住，主花色的 `AA` 对压不住。
  次序就是 大王 > 小王 > 主5 > 副5 > 主花色 AKQJ…2（文档第 62 行）。

- **换底牌是从 33 张里挑，不是从 25 张里挑。** 文档第 22 行：
  "叫的牌就把锅底的 8 张牌拿上去，在手上换牌，根据自己的情况去换牌，返回丢掉 8 张牌进入锅底。"
  所以流程是：锅底 8 张先摊出来给你看 → 合进手牌变成 33 张 → 从 33 张里扣 8 张 → 剩 25 张在手上，
  扣出去的 8 张成为新的锅底。
  2026-10-06 用户看截图时发现的：之前我写成了只从原来的 25 张里挑，等于锅底那 8 张根本没给玩家看——
  这是个会改变打法的实质错误，不是显示问题。测试见 `BottomSwapTests`。

## 三点五、2026-10-06 修的一个比大小 bug：散牌压过了连对

用户实机撞到：大无主下南家领 `♠K♠K♠A♠A` 连对，北家跟了一手同花色但连不起来的
`♠7♠10♠J♠Q`，结果判**北家最大**。

根因不在牌型识别（`ComboRecognizer` 认连对时是有同花色校验的），在 `TrickEvaluator.Strength`
**跨牌型直接比 `Key`**，而两种牌型的 `Key` 根本不是一个量纲：

- 连对的 `Key` 是 `TractorRank` = **自然序**（打 10 时 A 约等于 12）
- 对子/散牌的 `Key` 是 `Order` = **牌力次序**（`OffSuitBase` 1000 + 自然序）

`1000 + 10` 当然大于 `12`，散牌就这么"赢"了。

修法：领出是对子/拖拉机时，跟牌必须凑出**同样的牌型**，否则一律按垫牌（战力 0）算。
`ComboComparer.Compare` 遇到牌型不同是直接抛异常的，说明"不同型不可比"这个前提本来就是共识，
只是 `TrickEvaluator` 绕过了它。测试见 `TrickEvaluatorTests.同花色的散牌压不住连对`。

**同一类问题还有一处没动**：领出是**甩牌**时（`TrickEvaluator.Strength` 第一个分支），
如果杀牌的一方出的是主牌**连对**，它的 `Key` 同样是自然序，会被另一家全主散牌杀牌的
牌力次序盖过去。目前够不着——合法甩牌要求"别人手上没有比这手最小那张更大的牌"
（`ThrowRules.IsLegal`），同花色跟牌本来就赢不了；但两家都用主牌杀、其中一家恰好成连对时
会露出来。真要修得把 `TrumpContext` 一路传进 `TrickEvaluator`（现在签名里没有），
或者给 `CardCombination` 多存一个"最高牌力次序"，改动面不小，先记在这儿。

## 五、文档没说清、我自己定的地方（**有疑问就问这里**）

下面每一条都是文档没写、或者写得不够清楚，我自己拿主意定的。
都集中在少数几个地方，想改的话改动量都很小。

### 规则相关的

1. **庄家叫不起、闲家接庄时，闲家用自家的级牌叫主。**
   例：东西打 10 坐庄但叫不起，南北打 5，那南北用自己的 5 去叫，本局级牌随之变成 5。
   依据是文档第 93 行"当前牌局的等级，按照庄家的计算，本局庄家"。
   如果你们那边是沿用原庄家的级牌，改 `GameEngine.OnCallingExhausted` 一处。

2. **闲家 85~114 分（抢主局）按"等级和庄闲都不变"处理。**
   文档第 45 行说抢主局"相当于谁都没有赢"，但真正的抢主流程排在第二轮。
   所以现在这一段分数既不让闲家升级，也不让庄家掉级。
   跑 `tools/FanKou.Trace` 时会直接打出"抢主局（第一版按不变处理）"，不会悄悄混过去。

3. **出牌顺序是 东 → 北 → 西 → 南（逆时针）。** 文档没有明确写座位顺序，我按这个定的。
   屏幕上自己（南）在下方、东家在右手边，所以这是逆时针转。
   （这里原先写的是"东 → 南 → 西 → 北"——那是**发牌**顺序，不是出牌。
   2026-10-06 写《玩法说明.md》时对着 `Seat.NextInPlay()` 核过，已改正。
   同一件事见下面的第 7 条和第六点五节。）

4. **"让队友叫牌"补了一个条件**：只有当队友叫得起、**而且队友还没让过**的时候才可以让。
   少了后半个条件，两个队友会互相让到没人叫，那是违反文档第 51 行"有牌必须叫"的。

### 界面相关的

5. **你固定坐在下方（南家）。** 还没有换座位的功能。
6. **手牌排序**：主牌排最前，然后各门副牌，每门从大到小；两副牌的同名牌靠小圆点区分。
7. **方位按罗盘习惯**：自己在下、对家在上、**东家在右手边、西家在左手边**。
   出牌顺序因此是 东 → 北 → 西 → 南（逆时针）。表盘上的出牌区和两侧的座位名牌用的是同一套方位。
8. **节奏**（都在 `GameController` 顶部，改一个常量的数字就行）：
   - `AiThinkDelayMs = 620`：电脑"思考"多久
   - `TrickPauseMs = 1500`：一轮四人出完停多久，让人看清这轮出了什么
   - `DealRoundMs = 500`：发牌时每发一轮（四个人各一张）花多久。整副 25 轮 × 0.5 秒 = 12.5 秒。
     只在首局和以后的抢主局走这个慢发牌；点一下屏幕或按任意键可以跳过。
9. **叫主的明牌会摊在桌上**（叫主那个座位旁边），一直到正式打出第一张牌才收回去。
   这是按你说的加的，也对应文档第 56 行"叫牌的牌可以给别人看，这是明牌必须摆出来"。

## 六点五、发牌途中抢主（2026-10-06 用户补充）

这一条是用户当场纠正的，之前我把它做成了纯动画，理解错了。要点：

- **慢发牌不是给人看动画，是为了留出抢主的窗口**。发牌一张一张走，摸到能叫的牌当场就能叫。
  一次把牌全发完，抢先叫主就失去意义了。
- 所以引擎多了一个 `Dealing` 阶段，**由界面按节拍推着走**（`GameEngine.AdvanceDeal`），
  不是一口气发完。每发一轮检查一次有没有人叫得出来。
- 首局还没定庄，**各家用自己队的等级去叫**；叫成了，本局级牌就是他那一队的等级。
- 抢主**不给让牌的余地**（有牌必须叫），而且叫完了牌还得继续发完，发完才拿底牌换牌。
- 首局发到底都没人叫得出来 → 重洗重发（文档第 94 行）。

对应测试：`DealingTests.首局发牌途中就能抢主`、`DealingTests.抢主用的明牌后面不能扣进底牌`。

### 发牌方向与出牌方向是反的

用户明确：**发牌顺时针，出牌逆时针**。屏幕上东在右、南在下、西在左、北在上，所以：

- 发牌：东 → 南 → 西 → 北（顺时针），`Seat.NextInDeal()`
- 出牌：东 → 北 → 西 → 南（逆时针），`Seat.NextInPlay()`

代码里是两个不同的方法，别再合并成一个 `Next()`——之前就是因为只有一个 `Next()` 才搞错的。
测试在 `SeatOrderTests`。

## 六、卡牌样式（外部素材）

程序自带一套用代码画的牌面，同时支持外挂图片素材，**缺哪张自动退回自带画法**，
所以你可以只做几张先看效果，永远不会因为缺图崩掉。

- 扫描位置：`<exe 目录>\skins\` 和 `%APPDATA%\FanKou\skins\`
- 命名约定在 `Cards/CardFileNames.cs`，一张牌认好几种写法（`♠A` / `黑桃A` / `SA` / `spadeA`）
- 支持 png / jpg / jpeg / bmp / gif / webp，尺寸随意，按比例缩放不会拉变形
- 样式文件夹里放 `skin.json` 可以自定义显示名和作者
- 详细用法见 `skins\说明.txt`，菜单里也有入口

## 八、人机四档（2026-10-06 用户要求）

| 档位 | 实现 | 说明 |
|---|---|---|
| 入门 | `RandomBrain` | 只保证合法 |
| 简单 | `SimpleBrain` | 分牌/队友/省牌的基本判断，不记牌 |
| 普通 | `NormalBrain` | `SimpleBrain` + `CardMemory`（记外面还剩什么） |
| 困难 | `HardBrain` | 再 + `OpponentModel`（空门推断、对家没主牌了） |

配套的引擎改动：`GameEngine` 现在保留 `History`（每一轮谁出了什么、谁赢的），
`PublicBoardInfo` 把它连同叫主的明牌一起交给 AI。这些本来就是公开信息，
人打牌时都记得住，AI 不该比人傻。

### 调这一块时踩的坑（留个记录，别再走一遍）

量强度必须**配对**：同一个种子下一副牌打两遍，两家各坐一次东西。
不配对的话发牌运气会盖过实力差距——同一对档位换个种子区间，结果能从 +5% 变成 -30%。

试过但**更差**、已经回退的几条：

1. 把"安全"折成分数加进打分 → 贪图每墩都稳赢，大牌浪费在小墩上，比不记牌还差 30%。
   改成明确的取舍顺序（台面有分才求稳，没分就挑最省的）才好。
2. 领牌时躲着"对家可能要杀" → 过度保守，该冲的时候不冲。
3. 没分的墩干脆让了、把牌留着捡分 → 更差。能赢的墩还是该赢，赢了才有下一轮先手。

还发现一条：原来困难档的"概率折算"是**按比例缩放**威胁值，
缩放不改变排序，所以对决策**毫无影响**（实测两档成绩一模一样，1864 vs 1864）。
换成"对家都没主牌了 → 外面剩的主杀不到我"这种会改变判断的硬推断才有用。

### 实测结论

简单 ≫ 入门；普通比简单 **+2.8%**；困难比普通 **+0.6%**。
困难档确实在用推算做判断，但底层出牌模型本身粗，这点推算换来的胜率优势很小。
想让它明显更强得换思路（往前算一两步），不是加规则能解决的。测试如实写成"不弱于"，没吹。

## 九、顶牌（甩牌里的特例，2026-10-06 用户纠正后实现）

用户纠正：不是 `AKK/AQQ`，是 **`AAK/AAQ`**。规律是"**这门里最大的两张 + 次大的一张**"：

- 打 5 时副花色最大三张是 `AAK`
- 打 K 时 K 被提成主牌、从副花色里拿掉了，那一门最大三张变成 `AAQ`
- 大无主下级牌不再是主牌，所以还是 `AAK`

**为什么它必然合法**：两副牌每门只有两张 A，谁也凑不出三张 A 来压它——
它就是这门里最大的散牌。文档第 91 行说的就是这个道理。

实现要点：

- `ComboRecognizer.TopTripleRanks(suit, context)` 算出这门当前的最大/次大点数，
  判据是"按当前局是不是主牌过一遍"，不是写死 AAK
- 识别成 `ComboType.Throw`（**不是对子**），只认副花色（主花色里的牌本来就是主牌，不套这条）
- 跟牌：散牌规矩——有该花色先给，凑不够随便补，**不要求垫主**（文档第 72 行）
- 谁大：同花色散牌比大小；**要杀必须同张数且全是主牌**（文档第 72 行）
- 底牌倍率 `×2`（甩牌按两倍，文档第 92 行）
- 开关 `TopTripleIsThrow`，默认开

**顺带修的一个 bug**：`MoveGenerator` 里按形状去重时会把"两张一模一样的牌"压成一张，
导致跟三张牌时如果手上只有一对同名牌，候选枚举为空直接崩。
一万局自打抓到的，改成"按形状去重但保留最多 N 份"。

## 十、反主与抢主（2026-10-06 用户要求后实现）

### 反主

规矩（文档第 14、44、55、87、88 行）：

- 规格 叫主 &lt; 定主 &lt; 小无主 &lt; 大无主；**同规格不能反**
- **队友不能反，只有对手能反**
- 可以一直反，反到双大王（大无主）为止，到顶就没人反得动了
- **只改主牌和"谁拿底牌换牌"，不改庄闲、也不改谁先出牌**——
  先手永远是"叫主的那个庄家"（文档第 87 行原话）
- 只有**首局无庄**的时候例外：谁最后反成功，谁就是庄家

时机上有个不对称，文档里写得很明确，我按原样实现了：

| 局面 | 反主战的时机 |
|---|---|
| 首局（无庄） | **拿底牌之前**——"未决出庄家无法动底牌"（文档第 44、88 行） |
| 其它局（含抢主局） | **换底牌之后**——"换牌以后，才可以反"（文档第 45 行） |

反成功的人拿**当前的锅底**（也就是上一个换牌的人扣下去的那 8 张）接着换，
换完再问回去，形成一个链。每一步规格都严格抬高，所以最多走四步就到底了。

实现上是新加了一个 `CounterCalling` 阶段 + `NeedCall.IsCounter` 标记；
叫主和反主各有各的队列下标，**别推错了**——推错会一直问同一个人，卡到天荒地老。

### 抢主局

上一局闲家拿了 85~114 分（`RoundOutcome.GrabRound`）就触发下一局抢主：

- 下一局走**慢发牌**（一张一张发），因为"抢先叫主"发生在发牌这一段
- 双方各用**自家**的级牌去抢（`_perTeamLevel`）
- 抢到的那队保住等级，**没抢到的那队按保护规则掉级**（过 2 不掉，没过掉回 5）
- 抢主局本身"相当于谁都没赢"，等级和庄闲都不变（文档第 45 行）

这一块基本是把首局那套"发牌途中抢先叫主"的逻辑复用过来，正如用户说的"拿来套用"。

### 关于"跳过发牌"

用户明确要求**不做跳过**：玩家局里要四个人都同意才跳得掉，反而麻烦；
而且抢主就发生在发牌这一段，跳过了就没意义了。所以慢发牌期间不接受任何操作。
