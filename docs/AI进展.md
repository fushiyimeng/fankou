## 一、最重要的发现：这套 AI 的决定几乎全是"比大小"

现在的出牌逻辑是"给每个候选打一个分，挑最高的"。这类决策**只看数值的相对大小**。

后果很要命：**任何单调变换（把所有分数整体缩放、或者加一项在同类候选上等量生效的东西）
都只改数值、不改顺序，于是决策一模一样。** 模型看起来更"丰富"了，但一步都没变。

这一条能解释之前那几件怪事：

- 笔记里记着三次"改了反而更差、回退"——那些是真的改了顺序；
- 而 `+0.6%`、`+2.8%` 这种小到说不清的差距，很可能一部分就在这个区间里打转。

**做任何改动之前先问一句：这个改动会不会改变某些候选之间的相对顺序？不会的话就是白做。**

## 二、立了强度尺子（`tools/FanKou.Bench`）

之前缺的就是这个。旧的做法是"连打若干局看最后打到几级"，那个指标被
"谁先冲到 A 结束房间"主导，**噪声大到能把一次微小改动翻出 3.6%**（实测踩到过）。

新尺子的判据是**每一局谁把等级推进得更多**，并且：

- **配对**：同一个种子打两遍、A/B 换边，抵消发牌运气
- **样本大**：1000 个种子约 1.2 万有效局，本机 7 秒、N100 上 68 秒
- **给置信区间**（Wilson），分得清"真涨了"和"噪声"

```bash
# 本机
dotnet run -c Release --project tools/FanKou.Bench -- --a hard --b normal --seeds 1000

# 带置信区间和结论的一句话输出；--quiet 只打一行（丢服务器上用）
```

判据代码在 `src/FanKou.Ai/PairedEvaluation.cs`，**工具和测试共用同一份**——分成两份迟早跑偏。

### 用新尺子量出来的

| 对照 | 差在哪 | 笔记里的旧数 | 新尺子实测（约 1.2 万局） |
|---|---|---|---|
| 简单 vs 入门 | 会不会打 | 「一分没拿到」 | 没复测，差距明显 |
| 普通 vs 简单 | **记牌** | +2.8% | **+1.1%**（区间 50.2~52.1，**显著**） |
| 困难 vs 普通 | **空门推断** | +0.6% | **0.0%**（区间 49.1~50.9，**不显著**） |

**结论：现在的困难档和普通档打平。** 那层空门推断换不来可测的收益。
`AiLevelTests.困难档不弱于普通档` 的判据也已经换成新尺子，不再用噪声大的旧指标。

## 三、今晚改的两处（`c08a1a2`）

### 1. 庄家现在知道自己扣的底牌

`PublicBoardInfo` 多了 `Bottom`，**只给庄家、且只在他真正拿过底牌之后**
（首局的反主发生在换底牌之前，那会儿泄漏就是作弊）。

之前一律不传，等于让 AI 把自己埋的牌忘了——"我扣掉多少分就锁定胜局了"这类推算做不了。

### 2. 锅底不再被当成威胁（**但目前改不了任何决定**）

`CardMemory.ExpectedBeating`：按"每张真在别人手上的概率"折算锅底那 8 张。

但**在现有代码里它是恒等变换**：同一次决策里所有候选张数相同，权重是个共同常数，
而下游只拿威胁值排序——单调缩放不改变顺序。实测印证：改前改后困难对普通都是 50.0%。

留着是为了**将来搜索时语义是对的**（那时候要拿威胁值算期望，不能再用含锅底的假数字）。
**在那之前别指望它提升强度。**

## 五、下一步（按性价比排，还没做）

1. **分段效用**：现在的打分只看"这一手能拿几分"。但分的价值不固定——
   对手 115 分时那 5 分是命，对手 30 分时几乎为零。要按"离赢有多近"加权，
   而不是按分。**这条不用搜索就能改，而且是换目标、不是加特征。**
2. **残局精算**：剩最后几墩时分支很小，可以直接算到底。底牌倍率决定胜负的地方就在这儿。
3. **取样搜索**（真正的大头，以周计）：按公开信息抽一批"别人手上可能是什么"的完整局面，
   每个往下打到底，按效用加权取期望最大的那一手。需要信念模型 + 推演策略 + 时间预算。

搜索那一步的前置条件（`CaptureState`/`RestoreState`、出牌阶段不碰随机数）**已经有了**，
是之前做「撤回」时顺手打下的地基。

### 几条踩过的坑，别再走

- **别拿现在的困难档当推演策略**——推演要的是"不犯大错"，不是"很强"。
- **概率别用均匀抽样**：那抽的是"他可能是这些牌"，不是"他刚才那么出说明他大概是这些牌"。
  后者才是概率的来源。
- **自对弈调参必须有冻结锚点**，否则会优化成"专打上一个版本的自己"，分数涨、水平不涨。
- **改动前先问"会不会改变候选之间的顺序"**（见第一节）。
